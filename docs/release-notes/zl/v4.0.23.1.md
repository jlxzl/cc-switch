## 上游更新（v4.0.20 – v4.0.23）

## v4.0.20

本版本新增对 Oh My Pi 的支持，它是 CC Switch 管理的第 13 个应用：多个供应商可以同时写进它的 `models.yml`，MCP、Skills、提示词同步给 Oh My Pi，会话可以浏览和恢复，「应用」页可以安装、升级、卸载 Oh My Pi。「应用」页分成「已安装」「未安装」两组，已安装的应用可以拖动排序，侧栏跟着这个顺序。Kimi 官方账号的卡片现在可以编辑模型、从 Kimi Code 里移除；托管的 ChatGPT 账号可以用浏览器登录。另外修复了 DeepSeek 余额用完后显示成「套餐已过期」、Kimi Code 子代理的用量没有统计、Skills 更新一直报 HTTP 429、Pi 的 API Key 写成环境变量引用时额度查询 401、Claude Code 会话标题显示成 `<local-command-stdout>`、Linux 上开启应用级窗口按钮后页头拖不动等问题。4.0 完整的更新内容请见 [v4.0 发布说明](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-zh.md)。


### 新增

#### Oh My Pi

Oh My Pi（命令是 `omp`）现在是一个独立的应用，有自己的供应商、MCP、Skills、提示词和会话（[#6747](https://github.com/farion1231/cc-switch/pull/6747)、[#8308](https://github.com/farion1231/cc-switch/pull/8308)）。配置在 `~/.omp/agent`，用了命名 profile 时在 `~/.omp/profiles/<名称>/agent`；也可以在设置里改成别的目录。

- **供应商可以同时启用。** 和 Pi 一样，卡片上是「启用」「移除」，多个供应商同时写进 `models.yml`，在 Oh My Pi 里选用。只改 CC Switch 写的那一条，文件里其他内容原样保留；用了 YAML 锚点、标签这类写法的条目不会被重写，会提示你手动修改。
- **写入前按 Oh My Pi 的规则检查。** Oh My Pi 只要有一条供应商不合规，就会停用所有自定义供应商，所以填了它不接受的值，保存时会直接提示，不会写进去。只有旧版的 `models.json`、还没有 `models.yml` 时，会提示你先运行一次 `omp`，让它自己迁移，不会新建文件挤掉你原来的供应商。
- **添加供应商。** 表单和 Pi 共用，预设也来自 Pi 的目录；「获取模型列表」后在弹窗里勾选模型。「模型自动发现」（让 Oh My Pi 自己去接口查有哪些模型）和请求头、兼容选项一起放在「高级选项」里。API Key 可以写环境变量名，查询额度时 CC Switch 会按 Oh My Pi 的规则取出实际的值。
- **MCP、Skills、提示词。** MCP 写进 `mcp.json`，Skills 装进 Oh My Pi 自己的技能目录，提示词写进 `AGENTS.md`。Oh My Pi 还会从其他工具的目录里找 MCP 和技能，实际加载的可能比 CC Switch 里列出的多，MCP 和 Skills 页 Oh My Pi 一列的说明里有解释。
- **会话。** 可以浏览和恢复 Oh My Pi 的会话，预览里能显示项目里的图片。
- **「应用」页管理 Oh My Pi。** 用官方安装脚本安装（装了 Bun 就用 Bun，没装就下载官方的二进制），升级运行 `omp update`（用 Homebrew 装的仍然走 Homebrew），可以卸载。
- Oh My Pi 不经过本地路由，也暂不统计用量。

#### 托管 ChatGPT 账号可以用浏览器登录

在授权中心或 Codex 的供应商表单里添加托管 ChatGPT 账号时，可以在「登录方式」里选「浏览器登录」（[#8288](https://github.com/farion1231/cc-switch/pull/8288)、[#8284](https://github.com/farion1231/cc-switch/issues/8284)）。有些企业工作区关掉了设备代码登录，这些账号以前加不进来；重新登录也可以用浏览器。「设备代码登录」仍然可选。

### 改进

**「应用」页分成「已安装」「未安装」两组。** 每组标题带数量，没有应用的组不显示；刚打开、还在检测时先显示一整张表，检测完再分组，行不会一个个跳。Claude Desktop 没有命令可查，按是否装了 Desktop 来分组，行里照旧写是否已接入 CC Switch。

**已安装的应用可以拖动排序。** 鼠标移到某一行上，行首会出现拖动手柄，和供应商卡片排序一样。侧栏和默认打开的应用都跟着这个顺序；顺序只存在本机，不随云同步。

**Kimi 官方账号的卡片可以编辑和移除。** 以前官方卡片只能在授权中心管理，模型停在登录时的那一份。现在可以编辑卡片：连接和登录仍由授权中心管，这里只改模型，「获取模型列表」读取这个账号当前可用的官方模型，带上官方的上下文窗口、能力和思考档位。官方卡片也可以像其他 Kimi 供应商一样从 Kimi Code 里「移除」，卡片和登录都保留，再点「添加」就恢复；要删除，先移除，或者到授权中心删。

**没有 Kimi Code 套餐的 Kimi 账号显示「未订阅」。** 以前授权中心和官方卡片的额度一栏是空的，看起来像查询失败。

**余额用完也显示金额。** 余额为零或欠费时，供应商卡片和托盘以前只写「余额已用完」，看不出欠了多少，红字也和「额度查询失败」分不清。现在一律显示「余额 <金额>」，为零或负数时卡片上整行变红、托盘里变成橙色，和以前一样。

**额度查询失败的中文提示改成「额度查询失败」**（以前是「额度没查到」），供应商卡片、授权中心和托盘一起改。

**Pi 获取模型列表后在弹窗里勾选。** 以前只能逐行从下拉框里选，现在和 OpenCode、Codex、Kimi Code 一样弹出列表，勾选的模型自动加成一行，从预设或 models.dev 补上参数；取消勾选会删掉对应的行。逐行的下拉框还在。

**Pi 的请求头和兼容选项收进「高级选项」。** 默认收起，和 Claude Code、Codex 的表单一致；兼容选项的说明改成了白话。

**Claude Code、Claude Desktop 选 GitHub Copilot 供应商时，上游格式显示为「由路由按模型自动选择」**（[#8196](https://github.com/farion1231/cc-switch/pull/8196)、[#8195](https://github.com/farion1231/cc-switch/issues/8195)）。Copilot 的上游格式本来就按模型自动选，以前表单里还能手选，选了也不生效。

**用量页明细页签的数量一次全显示。** 以前「模型」页签要点开才有数量，切换应用时三个数量会消失再出现，页签栏跟着跳。

**价格表新增 Kimi K3.1 Pro 和 K3.1 Pro HighSpeed。**

**土耳其语翻译补全**（[#8616](https://github.com/farion1231/cc-switch/pull/8616)）。

**预设：** 各家预设的模型更新到当前的最新型号，填上 Key 就能用。

### 修复

- **DeepSeek 余额为零或欠费时，卡片和托盘显示「套餐已过期」，余额数字不见了**（[#8812](https://github.com/farion1231/cc-switch/issues/8812)）。DeepSeek 返回的「是否可用」只表示余额够不够调用，余额一到零就变成否，Key 本身仍然有效。现在照常显示余额；Key 真的失效时，仍按认证失败提示。
- **Kimi Code 子代理的用量没有统计进来**（[#8792](https://github.com/farion1231/cc-switch/issues/8792)）。Kimi Code 把每个子代理的记录写在单独的文件里，以前只读了主代理的那份。现在每个子代理都会导入，按每次调用记账，不会和主代理的汇总重复计算。
- **Antigravity 子代理和 ACP 会话的用量记成未知模型**（[#8693](https://github.com/farion1231/cc-switch/pull/8693)）。现在从 agy 本地的对话数据库里找回模型（只读，不会等 agy 写完）。
- **Skills 安装或更新一直报 HTTP 429**（[#8813](https://github.com/farion1231/cc-switch/issues/8813)）。下载 GitHub 仓库压缩包时没带 User-Agent，GitHub 对这类请求限流更严，多人共用一个出口 IP 时更容易碰到。现在会带上 `CC-Switch/<version>`。
- **Pi 的 API Key 写成 `$NAME`、`${NAME}` 这类环境变量引用时，额度和余额查询报 401**（[#8822](https://github.com/farion1231/cc-switch/issues/8822)）。以前把引用原样当成 Key 发出去，现在按 Pi 的规则取出变量的值；变量没设置时，也不会再把引用当成 Key 发出去。`!command` 形式的 Key，CC Switch 仍然不会执行。取出的值只用于这次查询，不写回配置。
- **Claude Code 会话在会话管理里的标题显示成 `<local-command-stdout>Set model to opus</local-command-stdout>`**（[#8799](https://github.com/farion1231/cc-switch/pull/8799)、[#8798](https://github.com/farion1231/cc-switch/issues/8798)）。会话一开头运行了 `/model`、`/effort` 这类本地命令时，标题会这样；最后运行了本地命令时，列表里显示的最后一条消息也是命令输出。现在会跳过这些记录。
- **Linux 上开启「启用应用级窗口按钮」后，页头拖不动窗口，窗口边缘也没有缩放光标**（[#8092](https://github.com/farion1231/cc-switch/pull/8092)、[#8091](https://github.com/farion1231/cc-switch/issues/8091)）。
- **Codex 经 Chat 上游时，带图片的孤立工具结果里，占位文字说图片在「下一条消息」里，实际并没有这条消息**（[#8157](https://github.com/farion1231/cc-switch/pull/8157)）。现在改成说图片已经作为图片附上。

## v4.0.21

本版本为 Claude Code 增加了多个官方订阅账号的切换：在授权中心添加几个 Claude 账号，每张官方卡选一个，切到哪张卡，Claude Code 就用哪个号；想几个号同时用，从卡片上「打开终端」，那个终端固定用卡片上的号。登录走 Claude Code 官方的流程，令牌只留在本机的 Claude Code 里，CC Switch 不上传、不刷新、不登出。绑了账号的卡片和授权中心都会显示每个号的套餐和剩余额度。另外，「打开终端」挪到了卡片上，Codex 的模型列表可以拖动排序，轻量模式重启后保持。修复了托管 ChatGPT 账号重启后误报登录过期、Codex 经路由时请求发到了别的地址、Codex 的 MCP 配置里多出 `timeout` / `autoApprove`、npm 12 下 OpenCode 和 Grok Build 装不好、Kimi Code 用量的时间不对、Oh My Pi 的 `models.yml` 里有 `&`、`*`、`!` 时无法编辑等问题。4.0 完整的更新内容请见 [v4.0 发布说明](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-zh.md)。


### 新增

#### 在多个 Claude 官方订阅账号之间切换

手上有不止一个 Claude 订阅（比如个人 Max 和公司 Team，或者多个 Pro 账号）时，以前只能在 Claude Code 里 `/logout` 再 `/login`，或者自己给每个号建配置目录。现在可以在 CC Switch 里管理多个号（[#1928](https://github.com/farion1231/cc-switch/issues/1928)）。

图文用法和逐条的合规对照见 **[使用 CC Switch 切换多个 Claude 官方订阅以及合规问题](https://github.com/farion1231/cc-switch/blob/main/docs/guides/claude-official-accounts-guide-zh.md)**。

**安全与合规。** 订阅账号交给工具管理，最要紧的是令牌安全、不违反 Anthropic 的条款。这个功能按 Claude Code 官方文档的做法实现，令牌始终只在你本机的 Claude Code 里：

- **登录走官方流程。** 添加账号时运行的是 Claude Code 自带的 `claude auth login --claudeai`，密码和授权都在 claude.ai 的官方页面完成。CC Switch 没有自己的 Claude 登录，也没有自己的 OAuth 客户端。Anthropic 的[法律与合规页](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use)要求 Claude 账号的登录必须通过 Anthropic 自己的流程完成，并且明确不限制用户用自己的订阅登录未经修改的 Claude Code。
- **多账号用的是官方推荐的方法。** 每个号一个独立的配置目录，用 `CLAUDE_CONFIG_DIR` 区分，和 Claude Code [认证文档](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts)里「Log in with multiple accounts」一节的方法一样，CC Switch 只是替你建好目录、打开终端。
- **令牌不离开本机。** 令牌只存在 Claude Code 自己的位置（macOS 的钥匙串，Linux、Windows 的 `.credentials.json`），不上传，不随云同步，也不写进 CC Switch 的数据库。CC Switch 自己只记邮箱、组织、套餐这类账号资料和登录过期时间，不记令牌。
- **不替你发请求。** CC Switch 没有服务器，不用订阅令牌调用模型；对话请求都由本机未经修改的 Claude Code 直接发给 Anthropic，用量计在你自己的账号上。查额度时在本机直接查 Anthropic 官方的额度接口，和 Claude Code 自己的 `/usage` 查的是同一份数据。
- **不刷新、不登出、不改 Claude Code。** 令牌一律由 Claude Code 自己刷新。删除账号只删 CC Switch 为它建的目录（macOS 上连同这个目录在钥匙串里的条目），不会让这个号在任何地方退出登录。CC Switch 不修改 Claude Code 的程序文件。
- **只管你自己的账号。** 不按额度自动轮换账号，也不提供把订阅共享给别人的功能。

切卡即切号会在本机 Claude Code 的存储位置之间移动登录（只按 Claude Code 自己的格式），官方文档没有专门讲到这种用法。只想用文档写明的方式的话，卡片保持「跟随 Claude Code 登录」，其他号只从卡片「打开终端」使用。

**怎么用：**

- **添加账号。** 在授权中心的 Claude 组点「添加账号」。浏览器会打开 claude.ai 的官方授权页，登录后账号自动出现在列表里。浏览器授权后回不到本机时，可以把地址栏里的地址或页面上的代码粘贴回来。每个号的目录互不干扰，会同步你在 `~/.claude` 里的设置、MCP 和 `CLAUDE.md`（登录凭据和路由相关的设置除外）。
- **给官方卡选账号。** Claude 官方卡的「登录方式」下拉和 Codex 官方卡一样：上面是已登录的账号，下面是「添加或管理 Claude 账号」（跳到授权中心）和「跟随 Claude Code 登录」。一个号建一张卡就行。
- **切卡即切号。** 切到选了账号的官方卡时，CC Switch 把这个号的登录放进 Claude Code 默认读取的位置，原来那个号放回它自己的目录。终端、IDE 插件、脚本里的 `claude` 都改用这个号，已经在运行的 Claude Code 也会立即跟着换，不用重启。切到选了账号的官方卡时，现在的登录如果还不在授权中心会先收进来。切换时持有 Claude Code 自己的锁；切换中途 CC Switch 意外退出的话，下次切换或启动时会自动补完或撤回。选「跟随 Claude Code 登录」的卡不碰登录，不添加账号的人不受影响。
- **几个号同时用。** 在选了账号的卡上「打开终端」，这个终端固定用卡片上的号，之后切换卡片不影响它。
- **套餐和额度。** 卡片副标题显示账号和套餐（如 `Max 20x`），登录需要更新时带一个提示；卡片底部默认显示这个号的剩余额度，授权中心里每个号也有一样的额度列。不在用的号令牌过期时，CC Switch 在它的目录里运行一次 Claude Code 自带的 `claude -p /usage`（每个号最多 10 分钟一次），由 Claude Code 自己刷新登录、查询额度，CC Switch 只读结果。`/usage` 不调用模型，不消耗对话额度。没选账号的官方卡也会显示当前登录的套餐。

几点注意：

- 切号后正在用的 Remote Control 会断开；换号后第一条消息要重建提示缓存，会慢一点、多用一点额度。
- 在设置里覆盖了 Claude 配置目录（包括指向 WSL）时，切卡不会切换登录，界面会提示改用「打开终端」。

#### Codex 的模型列表可以拖动排序

Codex 供应商表单里的模型列表，每行开头有拖动手柄，可以用鼠标或键盘调整顺序（[#8870](https://github.com/farion1231/cc-switch/issues/8870)）。这个顺序就是 Codex 里 `/model` 菜单的顺序。第一行代表默认模型时，拖到第一行的模型成为新的默认模型。以前要删掉再加回来才能挪位置。

### 改进

**「打开终端」挪到卡片上。** 以前在 ⋯ 菜单里，现在是「编辑」左边的一个图标按钮。悬停提示是「以此供应商打开终端」，终端固定用这张卡时（填了自己的地址和 Key 的卡、选了 Claude 账号的官方卡）会写「（环境隔离）」。

**授权中心每组的「添加账号」按钮固定在标题右边。** 以前没有账号时按钮会挪到空白提示里，几组卡片的按钮高低不一。ChatGPT 的登录方式改成按钮旁边的一个小下拉。标题里的「删除全部账号」菜单去掉了，账号在各自那一行的菜单里删除。各个账号的额度条现在对齐，长度一致。

**轻量模式重启后保持。** 在轻量模式下退出 CC Switch，下次启动仍是轻量模式，不再弹出主界面。从 `ccswitch://` 链接冷启动时照常打开主界面，好显示导入对话框。

**Hermes 卡片显示「默认」，「设为默认」移到 ⋯ 菜单里。** Hermes 把添加的供应商都写进 `config.yaml`，当前那家只是默认值，和 OpenClaw、OpenCode、Kimi Code 一样。以前的电源图标「启用」按钮看起来像开关。

**卡片变成「使用中」时，用量一栏不再左右挪动。**

**MCP 选了 SSE 时提示哪些应用不支持**（[#8882](https://github.com/farion1231/cc-switch/issues/8882)）。Codex 只支持 stdio 和 HTTP，会把 SSE 地址当作 HTTP 连接，服务端只支持 SSE 时连不上；Pi 和 Antigravity 保存时会报错。现在「写入到」下面会提前提示。

**Claude Desktop 的上游地址填 `githubcopilot.com` 时，上游格式显示为「由路由按模型自动选择」**（[#8838](https://github.com/farion1231/cc-switch/pull/8838)），和选 GitHub Copilot 供应商时一样。

**OpenCode 的 OMO、OMO Slim 卡片不再显示「检测连通」**（[#8842](https://github.com/farion1231/cc-switch/pull/8842)）。它们只是代理和模型的对应关系，没有地址可测，以前点了会报错。

**土耳其语翻译补全**（[#8836](https://github.com/farion1231/cc-switch/pull/8836)）。

**预设：** DeepSeek 一律改用 Flash 模型；Kimi 官方预设加入 K3.1 Pro 和 K3.1 Pro HighSpeed，可以选 low / high / max 思考程度（[#8867](https://github.com/farion1231/cc-switch/issues/8867)）；OpenClaw 的 MiniMax M3.1 Flash 可以选 max；新增 ClinePass（[#8885](https://github.com/farion1231/cc-switch/issues/8885)）、TeamoRouter Claude（[#8266](https://github.com/farion1231/cc-switch/pull/8266)）；Claude Desktop 的 OpenCode Go 改用官方文档的地址，额度也能查了（[#8720](https://github.com/farion1231/cc-switch/pull/8720)、[#8779](https://github.com/farion1231/cc-switch/issues/8779)）。

### 修复

- **托管 ChatGPT 账号重启后显示「登录已过期」、不能切换，过一会儿又自己好了**（[#8901](https://github.com/farion1231/cc-switch/issues/8901)）。以前刷新登录时遇到任何 HTTP 403 都当成登录失效，网络错误也显示成过期。现在和 Codex CLI 一样，只有 401 或明确的令牌失效错误才算过期；一时的网络问题照常重试，额度保留上一次的结果。托盘切换后，主界面里查询失败的额度也会重新查询。
- **Codex 经本地路由时，请求发到了别的地址**（[#8849](https://github.com/farion1231/cc-switch/pull/8849)、[#8848](https://github.com/farion1231/cc-switch/issues/8848)）。`config.toml` 里有多个供应商表、或上面有一行注释掉的旧地址时，以前取的是文本里第一个 `base_url`，会带着选中供应商的 Key 发到别处。现在按 `model_provider` 选中的那张表取地址。
- **Codex 远程压缩的用量有时漏记**（[#8879](https://github.com/farion1231/cc-switch/pull/8879)）。
- **Codex 的 MCP 配置里多出 `timeout`、`autoApprove`，Codex 桌面版报未知设置，`--strict-config` 拒绝加载**（[#8843](https://github.com/farion1231/cc-switch/issues/8843)）。这两个字段是别的客户端的，以前原样写进了 `config.toml`，手动删掉下次同步又会写回来。现在写给 Codex 时去掉，其他应用不受影响。
- **Codex 经中转连到多个 Azure 资源时，会话中途报 400「created under a different Azure OpenAI resource」，无法继续**（[#8877](https://github.com/farion1231/cc-switch/issues/8877)）。现在收到这个错误后重试一次，去掉历史记录的条目 ID。正常的请求不受影响。
- **ClinePass 这类把 Chat Completions 结果包在 `data` 里返回的上游，非流式请求报 422「No choices in response」**（[#5658](https://github.com/farion1231/cc-switch/issues/5658)）。
- **npm 12 下，「应用」页装的 OpenCode 在 Windows 上报「与你运行的 Windows 版本不兼容」，Grok Build 升级后仍在跑旧版本**（[#8863](https://github.com/farion1231/cc-switch/issues/8863)）。npm 12 默认不运行安装脚本，这两个包要靠它放置真正的程序。现在安装和升级时允许它们的安装脚本。
- **Windows 上 Hermes 在「应用」页显示成两处安装**（[#8839](https://github.com/farion1231/cc-switch/issues/8839)）。同一目录里遗留的 `hermes.cmd` 不再算一处安装。
- **Kimi Code 的用量，一整轮对话的请求时间都一样，按小时统计时挤在最后一小时**（[#8899](https://github.com/farion1231/cc-switch/issues/8899)）。现在按每次请求完成的时间记。已导入的记录在会话文件下次变化时会更正。
- **Oh My Pi 的 `models.yml` 里有 `name: Search & Fetch` 这类含 `&`、`*`、`!` 的值时，保存供应商时报「此 YAML 使用了 CC Switch 无法安全编辑的格式或语法」**（[#8897](https://github.com/farion1231/cc-switch/issues/8897)）。
- **`~/.gemini/.env` 里写成 `export GEMINI_API_KEY=...` 时，导入后没有 Key，切回默认供应商还会把它从文件里删掉**（[#8862](https://github.com/farion1231/cc-switch/pull/8862)、[#8861](https://github.com/farion1231/cc-switch/issues/8861)）。
- **从启用了提示词的项目切到没有提示词的项目，原来的提示词没有停用。**
- **用量统计页展开或收起侧栏时，趋势图右边缘跳动**（[#8548](https://github.com/farion1231/cc-switch/pull/8548)）。

## v4.0.22

本版本新增对 DeepSeek Harness 的支持，它是 CC Switch 管理的第 14 个应用：供应商一起写进它的 Web 和 Desktop 配置，MCP、Skills、提示词同步给它，会话可以浏览，「应用」页可以安装、升级、卸载；还可以在授权中心登录 DeepSeek 账号、查看余额，用量也会统计。Oh My Pi 的用量现在也会统计。「打开终端」可以勾选跳过权限确认、追加启动参数，Codex 卡片也能打开终端；WebDAV 配置可以清除；Skills 可以打开目录、在发现页查看文档；GitHub Copilot 的 Claude 模型改走原生接口，提示缓存命中率大幅提高。另外修复了 macOS 上连了 OAuth 远程 MCP 时切换 Claude 账号失败、开了全局代理时添加 Claude 账号报 403、Claude Desktop 新会话默认用 Fable、MiniMax 周额度用完后不显示、没在用的供应商余额不自动刷新、请求被转回路由自己导致内存暴涨、Gemini 工具调用报 400、xAI 拒绝 Codex 0.163 的请求、请求日志里存下整页报错把数据库撑大等问题。4.0 完整的更新内容请见 [v4.0 发布说明](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-zh.md)。


### 新增

#### DeepSeek Harness

DeepSeek Harness（命令是 `dsh`）现在是一个独立的应用，有自己的供应商、MCP、Skills、提示词和会话（[#8795](https://github.com/farion1231/cc-switch/pull/8795)、[#8986](https://github.com/farion1231/cc-switch/pull/8986)）。配置在 `~/.dsh`，设了 `DSH_HOME` 时以它为准。

- **Web 和 Desktop 一起管理。** DeepSeek Harness 的网页版和桌面版各有一份配置（profile），CC Switch 把供应商和 MCP 同时写进两份，缺的那份会自动建好；已经初始化的 headless、acp 也一起写。侧栏只有一个 DeepSeek Harness，「已添加」标题旁注明 Web 和 Desktop 共用这份列表。某一份被手动改得和另一份不一样时，编辑会被拒绝并提示，不会覆盖你的改动。
- **供应商可以同时添加。** 和 OpenCode 一样是「添加」「移除」，多个供应商同时写进去，在 DeepSeek Harness 里选模型。支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 三种接口，预设来自 Pi 的目录。API Key 写进 DeepSeek Harness 自己的凭据文件 `.credentials.yaml`，配置里只放引用；配置里的其他插件设置原样保留，写入失败会回滚。
- **模型编辑。** 思考、图片输入用开关，上下文长度和最大输出单独填，和 Pi、Kimi Code 的模型行一样；DeepSeek Harness 还可以设置可选的思考档位和每个模型的接口兼容选项。OpenCode、MiniMax Code 的模型编辑也改成了这个样子。
- **DeepSeek 账号登录。** 在授权中心的 DeepSeek Harness 组用浏览器登录 DeepSeek 账号，显示余额和赠金；Web 和 Desktop 共用这份登录，在任一处登录或退出，两边同时生效。添加供应商时选「DeepSeek 官方登录」会跳到授权中心。登录后，账号以一张官方卡显示在「已添加」最前面，账号下的模型由 DeepSeek Harness 自己提供，这张卡不能编辑，退出登录后自动消失。
- **MCP、Skills、提示词。** 支持 stdio 和 Streamable HTTP 两种 MCP。
- **会话和用量。** 可以浏览 DeepSeek Harness 的会话（含思考过程和工具调用）；恢复和删除会话请在 DeepSeek Harness 里操作。用量从会话记录导入，走 DeepSeek 账号的请求在用量页单独显示为「DeepSeek 账号（OAuth）」。
- **「应用」页管理 DeepSeek Harness。** 用 npm 安装、升级、卸载 `@deepseek-ai/dsh`，卸载不删你的数据。
- DeepSeek Harness 不经过本地路由。

#### Oh My Pi 的用量统计

用量页现在会统计 Oh My Pi 的用量，有自己的应用分类（[#9046](https://github.com/farion1231/cc-switch/pull/9046)、[#8939](https://github.com/farion1231/cc-switch/issues/8939)）。子代理的用量、对话之外的模型调用也会算进去，首次导入会包括以前的子代理会话。Oh My Pi 和 Pi 用同一个会话目录时，各自只导入自己的会话。Pi 已导入的数据不用重新导入。

#### 「打开终端」可以跳过权限确认、追加启动参数

「打开终端」对话框多了两项（[#9008](https://github.com/farion1231/cc-switch/issues/9008)）：

- **跳过权限确认。** 勾选后 Claude Code 和 Antigravity 以 `--dangerously-skip-permissions` 启动，Codex 以 `--dangerously-bypass-approvals-and-sandbox` 启动。默认不勾。
- **附加参数（可选）。** 填 `--debug`、`--append-system-prompt "Be concise"` 这类参数，接在启动命令后面。用空格分隔，含空格的值用引号括起来，最多 16 个。参数只作为参数传给程序，不会被当成命令执行。

两项都只用于这次打开的终端，不写进任何配置；终端打开成功后，CC Switch 会按应用记住你的选择。

#### Codex 卡片也能「打开终端」

以前 Codex 卡片上没有这个按钮。现在第三方卡片打开的终端只用这张卡：以 `codex -c ...` 启动，不改 `config.toml`，Key 通过环境变量传入，不出现在命令行里。当前供应商在 `config.toml` 里留下的设置会尽量改成不影响这张卡的值，改不了的（比如请求头、指定的 profile）会提示先切到这张卡再打开，避免当前供应商的 Key 被发到别处。当前使用中的卡直接启动 `codex`。

#### 清除 WebDAV 配置

以前配好 WebDAV 同步后，只能关掉自动同步，地址、账号、密码一直留在本机（[#8977](https://github.com/farion1231/cc-switch/issues/8977)）。现在 WebDAV 同步设置里有「清除配置」按钮，确认后从本机删除这些信息并停止自动同步；云端已上传的数据不会删除。

#### Skills：打开目录、复制名称、查看文档

- **已安装的 Skill**（[#8993](https://github.com/farion1231/cc-switch/pull/8993)）：⋯ 菜单里可以「打开目录」，在文件管理器里打开这个 Skill 的文件夹；点击 Skill 名称就能复制名称。原来的「复制目录名」去掉了。
- **发现页**（[#9039](https://github.com/farion1231/cc-switch/issues/9039)）：每一行多了「打开文档」按钮，安装前可以先看说明，没有文档时打开仓库主页。

### 改进

**GitHub Copilot 的 Claude 模型提示缓存命中率大幅提高**（[#8908](https://github.com/farion1231/cc-switch/pull/8908)）。以前 Copilot 的 Claude 模型一律转成 Chat Completions 格式发送，会丢掉缓存标记，Claude Code 在对话中途插入的系统消息还会打断缓存。现在 Copilot 支持原生 Anthropic 接口的模型直接走原生接口，Copilot 企业版长会话的缓存命中率实测从约 35% 提高到约 95%。

**Claude 配置目录在 WSL 里时，授权中心直接说明暂不支持 Claude 账号**，「添加账号」「重新登录」不可用。以前会让你改用「打开终端」，但这时打开的是 Windows 里的 Claude Code，同样用不了。

**MCP、Skills 列表悬停勾选框时不再同时弹出两个提示**；问号帮助卡片改为显示在右边，不再挡住鼠标，长内容会换行、在卡片里滚动（[#8593](https://github.com/farion1231/cc-switch/pull/8593)）。

**从别处跳到授权中心的某一组时，页面其他部分不再跟着移动**（[#8964](https://github.com/farion1231/cc-switch/pull/8964)）。

**OpenCode、OpenClaw、Hermes 的配置文件读不了时，供应商页会显示错误**（[#9044](https://github.com/farion1231/cc-switch/issues/9044)）。以前页面像从没配置过一样空着，添加供应商失败后才看到报错，还会留下一条多余的记录。

**托管的 ChatGPT、xAI 账号登录过期时，提示改为「请在授权中心重新登录这个账号」。** 以前提示运行一条并不存在的命令。

### 升级说明

**数据库版本从 23 升到 24**，为 MCP 和 Skills 增加 DeepSeek Harness 的开关。升级前会自动备份数据库；升级后再退回旧版本，旧版本会提示数据库版本过新，打不开。

### 新增

#### Kimi Code、MiniMax Code、Oh My Pi 的供应商编辑器按原生格式显示

以前这三个应用的供应商编辑器显示的是卡片的 JSON，和它们实际的配置文件对不上，上游文档里的配置片段也贴不进来。现在编辑器只显示配置文件里这一家的部分，位置和格式都和文件一致：

- **Kimi Code**：`config.toml` 里的 `[providers.<key>]` 和它的 `[models."..."]` 表。
- **MiniMax Code**：YAML 里的 `custom_provider.<key>`。
- **Oh My Pi**：`models.yml` 里的 `providers.<key>`。

标题显示实际的文件路径，会跟着目录覆盖和 `KIMI_CODE_HOME` 这类变量变化。草稿有格式错误、写了别家的节点、或者写了 `default_model` 这类全局设置时会提示并拒绝保存，改好之前上方的表单字段暂时不能改，避免把草稿覆盖掉。在编辑器里写的注释不会保存。DeepSeek Harness 的供应商在 profile 补丁里，仍用 JSON 编辑器。

#### 经路由连 Gemini 时，思考档位也能发过去

以前 Claude Code、Claude Desktop 经路由转成 Gemini 原生格式时，客户端选的思考档位和「关闭思考」都被丢掉，Gemini 一律用模型的默认设置。现在按 Gemini 自己的 OpenAI 兼容接口的换算方式发：

- **Gemini 2.5**：低、中、高分别是 1024、8192、24576 的思考预算。关闭思考时 Flash 和 Flash-Lite 发 0，Pro 不能关，发最小的 128。
- **Gemini 3 及以后**：发 low、medium、high 档位（Gemini 3 Pro 没有 medium，发 high）。这些模型都不能关闭思考，关闭时发支持的最低档。
- 认不出的模型、图片和语音这类模型、名字里已经带档位的中转别名（如 `gemini-3-pro-high`）不发，请求里本来没有思考设置时也不发。

#### 授权中心「全部刷新」

授权中心页头多了「全部刷新」按钮，一次重新查询页面上所有账号的额度（DeepSeek 是余额），各行照常显示更新中（[#9073](https://github.com/farion1231/cc-switch/pull/9073)）。

### 改进

**Claude Code、Claude Desktop 经路由连 OpenAI 格式的上游时，思考档位能发给更多模型**（[#9062](https://github.com/farion1231/cc-switch/issues/9062)）。以前只有 o 系列、GPT-5 以上和 Grok 4.5 以上会收到思考档位，DeepSeek 等其他模型静默丢掉，日志里也没有记录。现在：

- 认得出的供应商按它支持的档位发，比如 DeepSeek 发 low、high、max，OpenRouter 最高到 xhigh；Kimi、GLM、Qwen、MiniMax 这类 OpenAI 接口不收这个参数的不发。
- 认不出的上游只发 low、medium、high，选 xhigh、max 时发 high。
- GPT-3.5、GPT-4、Llama、Mistral 不发；关掉思考时不发。
- 两个应用的供应商表单在这两种格式下多了「思考档位」：「自动（推荐）」按上面的规则发；「原样发送」客户端选哪档发哪档，上游不支持 xhigh 或 max 时会报错；「不发送」用于上游因这个参数报错的情况。托管账号的卡片不显示这一项。

Codex 经路由连 DeepSeek 时的档位换算也改成和 DeepSeek 官方一致：minimal、low 发 low，medium、high、xhigh 发 high，max 发 max。以前 low 会被提到 high，xhigh 会被提到 max。

**Antigravity、MiniMax Code 的用量记录有了耗时和首字时间。** 以前这两个应用的用量里没有速度和首字时间。以前导入的记录也会补上。

**Skills 的发现页和已安装页改成同一种行样式**（[#9081](https://github.com/farion1231/cc-switch/pull/9081)）。仓库名用小号等宽字放在名称旁边，不再显示目录路径；「打开文档」按钮移到最右边；「已安装 · N 个应用」改成「已安装 ›」。从发现页点「已安装」跳过去时，那一行会黄色闪两下再恢复。

**托盘里绑了账号的 Claude 官方卡显示账号**（[#9071](https://github.com/farion1231/cc-switch/pull/9071)）。以前副标题都是 `www.anthropic.com`，有好几张官方卡时分不出来。现在有备注显示备注，没有备注显示账号（邮箱，没有邮箱时显示组织名）；账号不在这台电脑上时仍显示官网。

**Claude Desktop 路由模式下，Haiku 档的模型名改成 `claude-haiku-5-5`**（[#9096](https://github.com/farion1231/cc-switch/issues/9096)）。Claude Desktop 把 `claude-haiku-4-5` 当成旧模型，Haiku 档选不了思考档位。上游本身是旧版 Claude Haiku 时不改。直连模式不受影响。

**Grok Build 补上了 grok-4.6-build、grok-4.7-build、grok-4.7-build-fast 的价格**（[#9026](https://github.com/farion1231/cc-switch/pull/9026)）。

**预设：** 新增 OpenAI API Key 预设、13 家供应商的 Gemini CLI / Antigravity 预设（[#9089](https://github.com/farion1231/cc-switch/issues/9089)），以及讯飞 Astron MaaS 按量付费的 Claude Code 预设（[#9036](https://github.com/farion1231/cc-switch/issues/9036)）。
