本版本基于官方 v4.0.28（第 1 次 ZL 构建），同步官方 4.0.28 的全部更新。

## ZL 更新

- 新增 `POST /v1/messages/count_tokens` 及 `/claude`、`/claude-desktop` 两条同名路由。Claude Desktop 和 Claude Code 用这个接口数上下文长度；以前本地路由没有它，客户端会退回发一条带完整上下文、`max_tokens` 压到 1 的正式请求，聚合模式下这笔请求落到默认供应商的 opus 档，费用异常。现在按「设置里指定的供应商 → 当前供应商 → 本地估算」处理，只向 Anthropic 格式的上游透传，失败不影响正常路由，也不进熔断。
- 「设置 → 本地路由」新增「模型计数」，可以给 Claude Desktop 指定计数请求固定走哪家供应商，默认跟随当前供应商。
- 修复关于页把 ZL 版本误判为已同步。

## 上游更新

### 官方 4.0.28

- 适配新版 Codex 的会话分组：路由或聚合模式下切到第三方供应商时，会话与官方订阅留在同一组，来回切换都能继续；新增「统一 Codex 会话历史」开关，直连模式下也能把两边会话归到一组，并可迁入现有官方会话。
- 新增「暂停使用官方登录」：官方额度用完后 Codex 会锁住发送键，打开这个开关后可以继续使用第三方模型。
- Codex 官方额度保护改为默认开启，五小时使用率到 95% 或每周到 98% 时自动暂停官方请求。
- 应用页的安装、升级和卸载显示排队状态和实时进度。
- 不再写入 `disable_response_storage`；Antigravity 显示 Argon 每周额度；Windows 首次启动快约 6 秒。
- 修复 Codex 故障转移到别家时仍带着上一家的模型名、经路由连 Kimi For Coding 压缩上下文报 400、在 Kimi 或 DeepSeek 上续接工具调用后会话持续报 400、Windows 上 Codex 目录在 WSL 里时用量不导入等问题。
